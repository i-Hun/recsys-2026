# Как предложить правку

Спасибо, что читаете внимательно. Путеводитель собран вручную и большой, поэтому ошибки в нём точно есть.

## Issue или pull request

- **Не уверены, ошибка ли это**, или правка требует сверки с первоисточником — откройте issue по шаблону.
  Укажите адрес страницы и, если можно, место в статье (страница, таблица, раздел), где написано иначе.
- **Опечатка, битая ссылка, явная неточность** — сразу pull request.

## Как править

1. Найдите разбор: адрес `/stories/recsys-2026/papers/<slug>` → файл
   `public/stories/recsys-2026/articles/<slug>.json`, текст — в `sections[].markdown`.
   Краткое описание, вывод и ограничение карточки — в `data/recsys-2026.json` (элемент `papers` с тем же `slug`).
2. Правьте точечно, не переформатируйте JSON целиком: так дифф остаётся читаемым.
3. Числа меняйте только со ссылкой на источник (страница или таблица статьи) в описании pull request.
4. Запустите `npm ci && npm test`. Те же проверки CI запускает на каждый pull request.

Проверка гигиены (`scripts/test-recsys-hygiene.mjs`) отклоняет дефисные «слаги» из четырёх частей и больше,
например `some-internal-note-name`. Если это настоящий термин или имя модели, добавьте его в
`scripts/allowed-terms.json` в том же pull request.

## Что произойдёт дальше

`main` защищён: изменения попадают туда только через pull request с зелёным CI. После merge сайт
обновляется автоматически. Перед выкладкой проходит ещё одна редакционная проверка; если она что-то
остановит, вы увидите комментарий в pull request или issue.
